# Candidate discovery and recorded result curves

The user approved the recommended two additions with “弄”: find comparison
candidates and inspect settings alongside their recorded response curves. Their
priority remains cross-record research within the existing materials workspace.
This iteration does not add research notebooks or ontology interpretation.

## Chosen approach

Use transparent field criteria within the current accessible collection or
temporary selection, then reuse its ordered comparison pins. An opaque similarity
score would conceal missing metadata; a global search would broaden performance
and permission scope unnecessarily. The first selected record is the reference.
Users choose at least one field to keep equal and a different field to vary.
Only complete recorded fingerprints count as equal or different. Missing,
ambiguous and partial values are listed separately as uncertain candidates.
Known conflicts with the requested conditions are excluded. Show exact counts,
field evidence, bounded pages and a native link to compare each candidate.

Candidate results are not a statement that all other simulation settings match
or that the simulations are scientifically comparable. Existing field ordering,
precision, explicit units and conservative completeness rules remain authoritative.
Native checkbox criteria normalize to one canonical signed URL representation.
Criteria survive detail navigation, reference changes and saved relationships.

## Recorded result curves

Add a compact Result curves disclosure to Compare. Opening it explicitly loads
curves for the complete selected set; ordinary browsing retains scalar summaries.
Users choose a stress component (equivalent or one of six supported tensor
components) and total or plastic strain. Default to independent panels with
explicit units. Allow optional overlay only when every selected record has the
same quantities, component and recognized equal units. Do not convert units,
align curves, interpolate, reorder samples or infer material properties.

Clicking a curve or record highlights its corresponding comparison column and
pin. Preserve each record's actual sample indices, complete paired curve, loops,
zero and signed values. Expose unequal array tails and calculated-equivalent
origins; supplied equivalent fields remain authoritative even when empty.
Hover shows real samples, without pairing indices across different records.
Native controls and source detail links remain usable without JavaScript.

## Access and resource limits

Validate the entire selected set before reading curves, and recheck ownership,
membership and access for each request. Temporary requests also validate the
entire temporary selection. Do not reveal inaccessible titles or partial output.
Check actual stored JSON byte lengths before reading raw records: at most 16 MiB
combined and 100,000 paired samples per request. Over-budget requests explain the
limit and retain source-detail links instead of silently shortening curves.
Responses are private and not cacheable. No stored JSON or model migration changes.

Graph preparation, selected comparison and candidate discovery share one existing
25-record, 16-MiB and one-second request preparation budget. Warm discovery reads
summary caches only. An incomplete preparation step returns actual progress and
no partial candidate classification. No new dependencies or arbitrary global scans.
